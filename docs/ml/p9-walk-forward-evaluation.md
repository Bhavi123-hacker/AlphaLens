# P9 walk-forward evaluation

P9 is software research infrastructure. TEST_ONLY — NOT A PERFORMANCE CLAIM.
RESEARCH_FIXTURE — NOT PRODUCTION VALIDATED. Production-data clearance remains open.

The versioned `p9.walk_forward.v1` definition pins the P7 scoring dataset, P6 feature
dataset, canonical dataset/input, exact cutoff-specific P7 training dataset for each
fold, task, one of 1/5/10/20 sessions, families, seed, expanding folds, minimum sample
counts and embargo. There is no random split, rolling-window variant or tuning search.
Outer test intervals must be ordered, disjoint and later than the training cutoff.
All securities on the same session belong to the same temporal partition.

Every fold starts fresh. P7 training inputs must have `training_as_of` no later than
the effective training cutoff. They are generated by P7's existing label builder
and alignment with that cutoff, not by joining features and targets in estimator
code. A final-revision label dataset alone is insufficient: it could retroactively
replace what earlier training could know. Later P7 outcomes are a separate scoring
input. Each historical P6 plan contains only decisions already completed at that
cutoff; its P7 feature/label/dataset identities are separately pinned in the fold
model manifest. Training and scoring feature values/order and decision/universe
metadata must agree; no cross-sectional
feature is recomputed. All P7 exclusions remain authoritative and counted.

Effective cutoff = declared training cutoff minus `embargo_seconds`. Every training
decision and known label availability must be <= effective cutoff, and label
availability must strictly precede test local-date midnight (Asia/Kolkata). P7
unmatured/unavailable outcomes are excluded, not fabricated. Unknown target-end dates
are not inferred from calendar days. This conservative availability/maturity purge
protects overlapping target horizons. The next fold may train on earlier test rows
only once their outcomes are knowable at that next cutoff. It never rewrites the
earlier model or prediction.

The arena uses Logistic/Ridge, Random Forest and HistGradientBoosting from P8,
plus LightGBM 4.6.0 (MIT), CatBoost 1.2.8 (Apache-2.0), and XGBoost CPU 3.0.5
(Apache-2.0). All are local, free, pinned, CPU-only and single-threaded. Tree families
use 32 iterations/trees, depth 3 or P8's depth 4 forest, fixed modest regularization,
seed 1729 by default; no outer-test early stopping, evaluation set or parameter
search. P8 configurations remain unchanged. All enabled families receive identical
training/test rows and feature order for each fold. Training constant removal,
median imputation and Logistic/Ridge scaling fit TRAIN only. Ineligible missing
rows are never rescued. Targets convert explicitly from exact P7 values to float64.
LightGBM's imputer preserves consistent DataFrame column names. A small public
sklearn BaseEstimator adapter wraps CatBoost's older sklearn protocol; warnings
are not suppressed. CatBoost's plotting dependencies are installed but no UI or
hosted service is used. XGBoost's CPU distribution avoids GPU/NCCL dependencies.

Per-fold metrics include P8's complete classification metrics/confusion/calibration,
or regression MAE/RMSE/R², plus all naive metrics and deltas. Majority/positive rate
and zero/train mean use only permitted TRAIN. Stability reports retain fold sample
counts, mean, median, population standard deviation, best/worst metric values and
percentage of folds beating the predefined Brier/train-positive-rate or MAE/train-mean
comparator. No accuracy-only selection or automatic champion promotion exists.
Fixtures yield TEST_ONLY_CANDIDATE or INSUFFICIENT_EVIDENCE, never a production model.

Fixed cross-sectional diagnostics require at least five scored eligible securities
per session. They report Spearman rank IC (unavailable for constants), top/bottom
quintile mean realized target and spread, with deterministic security-ID tie breaks.
These are target diagnostics, not trading profit. No quantile optimization occurs.
Regime diagnostics remain unavailable without approved market-context inputs.
Uncertainty is unavailable for TEST_ONLY, fewer than ten folds or sixty test sessions.
Otherwise a descriptive Student-t interval of fold metric means is available, with
shared expanding-training history and approximate independence disclosed; it is
not a significance test. Negative control permutes TRAIN targets with a fixed seed
for the first predefined family per fold, retaining untouched test outcomes. An
apparent fixture success never becomes evidence of real predictive value.

OOS records are built exclusively from each fold's selected test rows. They retain
security/session/decision, availability, fold/run/family/task/horizon, prediction,
classification probability, nullable actual target and exact return text, target availability,
P6/P7/P5/P4 identities and unchanged classification. Outcome exclusions remain
explicit: feature-eligible test predictions survive missing/rejected future labels,
while metrics use only P7-accepted outcomes. This never upgrades TRAIN eligibility.
Otherwise an unknowable terminal outcome could silently erase a historical
prediction before P10 and introduce survivorship bias. Prediction availability equals
the original decision timestamp; this is historical simulation, not a claim the
model was actually trained on that historical wall clock. No TRAIN or tuned
validation record is accepted. Identity hashes pin all datasets/configuration,
resolved hyperparameters, preprocessing, environment, row membership and feature
order. P9 output schemas retain all required identity fields for P10.

Local outputs: walk-forward-manifest.json, fold-metrics.json, model-comparison.json,
oos-predictions.parquet, stability-report.json, negative-control-report.json, and
checksum-pinned fold model audit artifacts. JSON and Parquet ordering are stable.
Equivalent predictions/metrics are guaranteed in the pinned environment; serialized
model bytes are not claimed identical. skops files are stored for trusted local
engineering audit only: P9 exposes no arbitrary type-trusting model deserializer.
The OOS loader verifies hashes, schema, ordered uniqueness, model/fold membership,
classification, timing and input identity. Integrity hashes do not authenticate an
attacker-controlled manifest. Inputs must remain trusted local research artifacts.

The 90-session constructed fixture uses three expanding folds (test sessions
52–56, 60–64 and 68). Its calendar, securities, prices and benchmark are authored
TEST_ONLY evidence; no actual NSE universe or market-performance claim follows.
Real data can be replayed with new P7 cutoff-specific snapshots and definitions
without changing model or evaluation code. P10 is separately authorized only after
P9 passes and is committed. P11 onward remains unauthorized.
