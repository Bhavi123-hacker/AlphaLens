# Production forward outcomes and model readiness

This campaign adds an offline retry for the existing automatic outcome stage;
it does not introduce a new statistical study or alter frozen acceptance rules.
The prior daily worker already invoked reconciliation after capture and on
zero-request replay. The standalone command defaults to a read-only preview.
No live request, scheduler modification, backdated forecast or original model/
forecast/research replacement is authorized by this job.

Before inspecting current saved results, the maturation evidence policy is:
verify original forecast/target/horizon and chronology; require all five actual
subsequent per-security price slots; cross-check official session-link summaries
against saved raw official calendar responses, including every intervening closed
date; require source retrieval after session completion; reject unknown action
assessment, known action/quality exclusions and identity discontinuities. Missing
evidence remains pending. Raw closure contradictions fail closed. Only qualified
expanded forecast IDs may enter the existing append-only reconciler. Original
forecast records and the original V2 ledger are never rewritten. Shared dates
and overlapping horizons do not become iid evidence; the existing date-block
requirements remain unchanged.

The append command uses the existing daily kernel lock and transactional,
idempotent per-shard outcomes. A partial shard failure may leave prior committed
qualified references, which a restart replays rather than duplicates. It records
a separate immutable completion/failure receipt, with sanitized error codes.
Default preview neither opens a writable forecast database nor creates job files.

Current saved evidence, exact test results and independent model verdicts will be
appended after verification; no forward accuracy or economic acceptance is
inferred from implementation or fixture passes.
